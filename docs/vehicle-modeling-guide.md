# 写实车模制作与接入经验

本文记录本项目从程序化卢比肯原型，到详细车身、35 寸轮胎和实车参考底盘的改进过程，供后续制作其他车型时参考。

记录日期：2026-11-04。此次实际使用 Godot 4.6.1、Blender 5.1.0。文中的尺寸、材质数值和部件布置属于本次车型；接入其他车型时需要重新测量。

## 1. 先把工作放在最影响真实感的地方

建议按以下顺序推进：

1. 确认车型、年款、车身形式、轮胎规格和改装范围。
2. 检查已有资产，完成全车预览，再决定复用、修补或重新建模。
3. 校准轮廓、比例、轴距、轮距和轮胎尺寸。
4. 做好车身曲面、门窗结构、灯具和材质。
5. 对照实车照片补全底盘，接入转向、车轮滚动与悬挂。
6. 在同光照预览和实际游戏中验收，最后优化性能。

这次最有价值的发现是：经典轿车虽然面数较少，车身曲面和贴图却更成熟；早期卢比肯把大量面数用在轮胎和小零件上，门板、窗框和车顶仍然简化，整体看起来像拼装模型。

### 本次模型对比

| 项目 | 经典轿车 | 早期程序化卢比肯 | 本次改进后的卢比肯 |
| --- | --- | --- | --- |
| 三角面数，按实例计 | 26,142 | 429,922 | 282,741 |
| GLB 内嵌图片数 | 车身 7 张、车轮 3 张 | 0 | 21 |
| 主要特征 | 连续曲面与已有纹理 | 密集轮组、平直车身、统一材质参数 | 详细车身基础、补建四门硬顶、恢复与新增贴图 |

统计口径：轿车为车身加四个车轮；卢比肯包含备胎。均不包含运行时生成的底盘。图片数包含法线、粗糙度等数据贴图，不等于照片数量。以上是本次资产快照，后续修改可能改变数值。

早期卢比肯约 83% 的三角面集中在五个轮组。面数应优先服务于轮廓、曲面反光和可见结构，同时记录贴图体积、材质数量和实际运行表现，不能只看一个三角面总数。

## 2. 先做资产体检，再投入适配

### 检查项目和本机已有资产

先查看仓库、用户已提供的目录和相关本地下载资产。本次在 `~/Downloads/3D_model/car/` 找到了更详细的 Wrangler 车身基础，外观改进效率明显高于继续给原型堆零件。

拿到 GLB 后，先检查：

| 检查项 | 要回答的问题 |
| --- | --- |
| 完整性 | 是否包含车门、车顶、玻璃、内饰、底盘和备胎？ |
| 车型一致性 | 是两门还是四门？开放式还是硬顶？是否混入另一年款或改装版本？ |
| 尺度和坐标 | 单位是否为米？前方是哪条轴？原点、缩放和轮心位置是否合理？ |
| 节点层级 | 车轮能否拆出？哪些零件需要转向、滚动或随桥移动？ |
| 材质 | 文件里有图片吗？图片是否真正连接到材质？玻璃是否仍为透明材质？ |
| 几何 | 是否有重叠轮毂、重复面、隐藏高面数零件或远离车身的空节点？ |

GLB 的 JSON 数据可以直接统计网格、材质、图片和三角面；计算整车面数时要计入节点实例。GLB 文件大小本身无法说明模型是否精细，图片也可能占据主要空间。

**在修改资产之前，先拍前、侧、后、底部四个方向的预览。** 本次实际渲染后才确认本地模型是开放式车身，缺少车门和硬顶。如果一开始就做全车预览，可以更早明确需要补建哪些部分。

保存源包身份、文件名、已有作者与许可信息，以及本次改动说明。项目中的来源记录见 [ASSET_NOTES.md](../cars/Models/Rubicon/ASSET_NOTES.md)。使用外部资产后，应同步更新说明，准确区分原始资产与自己补建的部分。

### 区分精确复刻和风格改编

本次成品属于 JL 风格的游戏改编：车身基础带有开放式 392 风格细节，门顶为补建，底盘参考了其他 JL Rubicon 的实拍。它没有被验证为某一具体年款、动力配置的完整复刻。

下次若要求准确复现某一配置，开始前就应固定车身、发动机、变速箱、车桥和改装方案，使用对应参考。不同配置的排气、油箱及护板位置可能不同。

## 3. 把视觉模型和物理尺寸放在同一套坐标中

### 本项目的约定

| 项目 | 约定 |
| --- | --- |
| 长度单位 | 米 |
| Godot 车辆前方 | 局部 `+Z` |
| Godot 车辆上方 | 局部 `+Y` |
| Godot 车辆左侧 | 局部 `+X` |
| 车轮滚动轴 | 局部 X 轴 |
| 转向轴 | 局部 Y 轴 |

不要直接把本次导入脚本里的坐标变换矩阵用于另一台车。本次源模型在 Blender 中朝向 `+Y`，需要转换到项目的车辆前方约定，还需要重置轴距中点和垂直基准。

处理时先取得零件的世界变换，再明确把变换烘焙进顶点还是保留在节点上，避免两边重复应用。重建层级后检查左右轮、前后轮、法线方向与缩放。

### 用轮胎顶点测量实际外径

本次目标尺寸：

```text
35 英寸 × 0.0254 = 0.889 米外径
物理轮胎半径 = 0.4445 米
轴距 = 3.008 米
前后轮中心 Z = +1.504 / -1.504 米
左右轮中心 X = +0.875 / -0.875 米
```

将胎面顶点转换到轮心坐标后，沿车轮滚动轴的垂直平面测量：

```text
radius = max(sqrt(vertex.y² + vertex.z²))
```

测量应包含胎块最外端。包围盒适合检查整体尺寸，但其角点不一定在实际胎面上，不能直接把包围盒对角线当作轮胎半径。

调整轮胎时还应核对轮宽、轮毂尺寸及胎侧比例；一次整体缩放不一定能同时满足所有规格。随后让渲染半径、物理半径、轮心、轮眉间隙使用一致数据。

## 4. 分清车身、转向、滚动和悬挂的职责

建议保留明确的活动层级，例如：

```text
Visual
├── Model
│   ├── Body
│   ├── WheelFL        # 轮心位置与前轮转向
│   │   └── RotorFL    # 轮胎和轮毂滚动
│   ├── WheelFR
│   ├── WheelRL
│   └── WheelRR
└── Chassis            # 根据悬挂状态更新的底盘部件
```

车轮位置由同一组悬挂数据驱动：

```gdscript
var center: Vector3 = mount - Vector3.UP * suspension_length
wheel.position = center
wheel.rotation.y = steering if is_front else 0.0
rotor.rotation.x = wheel_roll
```

车桥、差速器和弹簧下座属于随轮桥移动的部件；车架、油箱和护板主要固定在车身上；传动轴、减震器和连杆跨接两端，需要更新位置、方向和长度。

合并网格时以“相同父节点、相同材质”为基本边界。保持活动轮组独立，也要保留玻璃与灯罩所需的材质边界。检查原资产中的静态轮轴、减震器和排气，避免与运行时生成的结构重复。

## 5. 车身真实感来自形体和连续反光

### 先做好大形状

优先核对发动机盖高度与倾角、车顶弧度、前风挡倾角、门板起伏、窗框厚度、轮眉形状和保险杠过渡。即使车型整体方正，实际钣金也有轻微曲率、折线、圆角和收边。

门窗需要有可读的结构层次：外板、门缝、门框、密封条、独立玻璃、内门板。仅放一块透明平面和几根细柱，会产生玩具感。

### 大面积面板避免中心扇形拓扑

本次补建门板时，最初把边界连到中心点形成三角扇，侧视反光出现明显的 X 形。后来改为连续四边形网格，控制轻微外凸、边缘圆角和厚度，异常反光才消失。

需要承载连续高光的大面板，应使用能够表达曲率的拓扑，并检查导出后的法线。增加细分之前先检查面板形状、光滑设置、重复面和法线，避免用面数掩盖结构问题。

### 标识必须贴合曲面

原始发动机盖标识的贴图匹配不正确，直接连接后出现了无关图案。补建文字后，又出现文字悬空、露出远侧车身轮廓的问题。

最终按发动机盖坡度调整文字高度，再使用 BVH 射线把文字顶点投到真实表面，仅保留很小的法向偏移。下次可以根据资产条件选择正确的贴花 UV、贴花网格或曲面投影，完成后必须检查正面、斜侧和远侧轮廓。

## 6. 材质要检查到游戏运行时

### 恢复材质连接

本次本地源 GLB 没有内嵌图片，许多材质只有默认灰色参数，但同级目录存在纹理文件。需要逐项恢复颜色、法线、粗糙度及透明通道。

文件名只能帮助定位，不能证明纹理与网格匹配。连接后要确认 UV、图集区域、方向和透明背景，尤其是仪表、车标、灯具和轮胎文字。

颜色贴图与法线、粗糙度等数据贴图应使用相应的颜色空间。本次数据贴图在 Blender 中设为 `Non-Color`。若增加细节纹理，保留原始图集 UV，另建如 `DetailUV` 的通道；法线节点及导出后的纹理坐标也必须对应正确通道。

### 用细微变化区分材料

车漆、塑料、皮革、轮胎和金属应分别处理。本次为车漆、内饰皮革、塑料和硬顶生成了固定随机种子的无缝法线、粗糙度贴图。它们提供细微表面变化；主要轮廓仍由几何表达。

当前车漆金属度 `0.32`、基础粗糙度 `0.27`，轮胎粗糙度 `0.84`。这些是本项目的调试起点，不能作为其他车型的通用配方。材质数值还需要在目标光照、曝光和观察距离下判断。

### 保持玻璃透明，并保留原有材质信息

玻璃使用独立几何，保留车内结构，结合反射、粗糙度和透明度判断效果。检查从车外看车内、穿过两层车窗，以及第一视角看道路三种情况。

运行时修正材质时，先复制导入材质，再修改必要字段，保留已有贴图。当前 [RubiconVisual.gd](../cars/RubiconVisual.gd) 专门处理透明玻璃和清漆；不要用一份通用材质覆盖整车。

Blender 预览正确仍需检查 Godot。实际读取运行时材质，确认法线、粗糙度贴图已连接、玻璃透明模式正确，最后用截图验收。

## 7. 底盘先理解布局，再增加零件

### 按系统看参考照片

至少收集底部全景、前桥、后桥和局部连接照片，标明车头方向与左右侧。搜索引擎对图片的描述只能作为线索，需要亲自辨认照片中的部件和观察方向。

| 系统 | 重点观察 |
| --- | --- |
| 车架 | 纵梁截面、起伏、横梁、车身安装座 |
| 传动 | 变速箱、分动箱、前后传动轴、差速器偏置、连接法兰 |
| 悬挂 | 上下控制臂、横向定位杆、弹簧座、减震器、限位块、稳定杆 |
| 转向 | 转向节、横拉杆、拖曳杆、转向减震器 |
| 制动 | 制动盘、卡钳、硬管及柔性软管的走向 |
| 保护与排气 | 油箱、托架、护板、隔热板、排气越桥路线和消声器 |

本次对照照片后，重点改进了起伏车架、带螺栓盖板的差速器壳体、偏置前差速器、油箱护板、越过后桥的排气和后部横置消声器。简单的球体差速器、贯穿车底的大平板和任意摆放的圆杆，很难表达真实底盘。

不同车型应分别确认整体桥或独立悬挂、驱动形式、车架形式和动力系统。卢比肯的整体桥布局不能直接套用到轿车或电动车。

### 杆件必须按局部轴缩放

本次曾出现轮轴长度不对、连接不到轮心的问题：圆柱沿局部 Y 轴延伸，却使用了世界方向的缩放。

对于高度为 1、沿局部 Y 轴的圆柱，构造朝向后应使用：

```gdscript
var basis := Basis(side, axis, side.cross(axis))
node.transform = Transform3D(
    basis.scaled_local(Vector3(1, a.distance_to(b), 1)),
    (a + b) * 0.5
)
```

其中 `axis` 是两端方向，`side` 是与其垂直的单位向量。计算时要处理两端重合，以及方向与参考轴平行的情况。完整实现可参考 [OffroadChassis.gd](../cars/OffroadChassis.gd) 的 `align_rod()`。

### 在全部悬挂行程中检查连接

除正常静态姿态外，还要检查同桥左右一压一伸、前后桥相反姿态、最大压缩、最大下垂和转向。需要确认轮轴接到轮心、传动轴接到接头、减震器伸缩连续，以及零件没有明显穿插。

当前底盘视觉跟随射线悬挂，连杆运动属于视觉近似，并非完整多刚体机械约束求解。以后若需要精确机械运动，应单独设计物理方案，不能仅凭外观连接就宣称运动学准确。

## 8. 保留可重建的管线，并控制处理成本

把源资产转换、补建车身、运行时底盘分开，记录输入源包和输出路径。游戏使用已导出的资产，不依赖玩家电脑上的 Blender 或下载目录。

本次遇到的管线问题：

| 问题 | 处理方式与经验 |
| --- | --- |
| Blender 节点名称受界面语言影响 | 按 `node.type == 'BSDF_PRINCIPLED'` 查找，避免依赖显示名称 |
| 逐项读写 UV 导致处理耗时很长 | 批量读取顶点、法线和索引，在 NumPy 中计算，再用 `foreach_set` 批量写回 |
| 源模型有远离车身的空节点 | 完成世界变换处理后清理无关定位节点，重新检查包围盒 |
| 轮毂表面重复 | 按轮组检查重复几何，保留必要的轮胎、轮毂和装饰面，去除真正的重复层 |
| 新旧排气、车桥叠在一起 | 先明确保留源资产哪些部件，再删除被新系统替代的静态结构 |
| 贴图导入后出现额外文件 | Godot 会提取 GLB 内嵌图片；检查这些文件与导入结果，而不是直接删除 |
| 旧生成脚本覆盖新模型 | 在文档中明确当前构建入口与历史原型脚本的区别 |
| 按部件拆分 GLTF 材质块后反光破碎 | JB74 导入器显式保存并恢复逐面角自定义法线；钣金和保险杠不做无差别焊接 |
| 轮胎减面后出现细缝、透出车身颜色 | 先合并同一轮组的材质块并焊接接缝，再减面；与外部钣金分开处理 |

优化时先考虑不可见的发动机内部、隐藏内饰、重复结构和过密的轮胎细节，保护车身轮廓、灯具、轮眉及近景可见区域。本次只对选定的隐藏发动机和内饰网格做简化，没有统一降低所有零件的精度。

现有导入器包含源模型节点名和坐标阈值，属于特定资产的适配脚本。下次应重新识别零件，必要时建立显式的部件映射表，不要把这些规则直接视为通用导入算法。

## 9. 验收分为画面、资产与驾驶三个层面

### 画面验收

使用固定光照、相机、焦距和显示尺寸，保存前斜视、正侧、后斜视、底部全景、前后桥近景与驾驶舱截图。对比旧版和新版时保持条件一致。

重点查看：轮廓比例、门板高光、窗框厚度、玻璃、灯具、轮胎间隙、标识贴合、底盘连接和驾驶员视线。还应进入实际场景检查环境反射、阴影、HUD 遮挡和鼠标环绕观察。

第一视角需要依据新车身重新校准。模型高度变化后，原来的视点可能进入车顶、头枕或仪表台。碰撞体也需要随真实外形调整，但不必为纯外观改动重调全部动力参数。

| 检查 | 本项目参考 |
| --- | --- |
| 实际轮胎网格外径、运行时贴图、玻璃 | [RubiconAssetChecks.gd](../tests/RubiconAssetChecks.gd) |
| 悬挂变化中的轮轴与传动轴端点、有限变换 | [ChassisChecks.gd](../tests/ChassisChecks.gd) |
| 选车、悬挂落稳、低速挡、复位、涉水、刹车 | [RubiconChecks.gd](../tests/RubiconChecks.gd) |

按改动范围选择检查。几何和材质变化需要资产与画面检查；修改碰撞体、轮心或视点后增加对应的驾驶、悬挂和相机回归。自动测试不能代替看图，单张好看的截图也不能证明车辆可以正常驾驶。

以下命令是当前卢比肯的重建与验收示例。运行前在项目根目录，并把源包路径和 Blender 可执行文件替换为实际位置：

```sh
blender -b -t 4 --python tools/import_rubicon.py -- --source /path/to/package
./run.sh --headless --editor --import --quit

./run.sh --headless --script tests/RubiconAssetChecks.gd
./run.sh --headless --script tests/ChassisChecks.gd
./run.sh --headless --fixed-fps 60 --script tests/RubiconChecks.gd
./run.sh --headless --fixed-fps 60 --script tests/CameraChecks.gd
./run.sh --headless --fixed-fps 60 --script tests/ParkingChecks.gd

./run.sh --script tests/RubiconRealismReview.gd --resolution 1440x810
./run.sh --script tests/ChassisVisualReview.gd --resolution 1440x810
```

两项视觉检查需要图形桌面，会分别生成 `/tmp/rubicon-realism-*.png` 和 `/tmp/chassis-Rubicon-*.png`。这些是临时预览，可通过脚本重新生成。

`tools/build_rubicon.py` 是旧程序化原型生成器，运行它会覆盖当前模型。当前版本应使用 `tools/import_rubicon.py`。
